## 一、入口与抽屉骨架

### 1.1 入口（TopBar）

| 入口 | 形态 | 行为 |
|---|---|---|
| 「AI 助手」按钮 | 顶栏右侧、角色切换器之前；ai 色徽章样式（✦ 图标 + 文字） | 打开抽屉 |
| 待确认建议徽章 | 存在 `source='ai'` 的系统边（含运行时新增候选）时显示「✦ N 条系统级建议待确认」，badge-ai | 打开抽屉（建议卡在对话流内可见） |

两个入口共用同一抽屉；徽章计数随确认/拒绝实时变化（§七）。

### 1.2 抽屉五段（480px 右侧固定层，遮罩 z-index 低于面板）

```

│ ┌────────────────────────────────────────┐ │ 面板 w=480px bg-card

│ │ ② 聚焦条  当前聚焦·{三级视图焦点} │ 🔒只读工具 │ │ h-9 bg-page border-b

│ │ ④ 消息滚动体                             │ │ role="log" aria-live="polite"
│ │    · 空态：示例问题 ×4（系统级主题）     │ │
│ │    · 用户气泡（右）/ AI 气泡（左）       │ │
```

- 抽屉与画布共存：打开时不遮挡顶栏，遮罩点击 / `Esc` / ✕ 关闭；关闭后画布保持联动结果（子图/选中边不回退）。
- 抽屉打开期间画布任何选中/层级变化都会刷新 ② 聚焦条（三级视图焦点透传，见 §三）。

## 二、LLM 状态（头部徽章 + 横幅）

| 态 | 头部徽章 | ③ 横幅 | 输入区 |
|---|---|---|---|
| 已配置 | `已配置 · <model>`（ai-soft 底、ai-deep 字、mono） | 无 | 可发送 |
| 未配置 | 「未配置」（中性 line/subtle 底） | warning：「AI 助手暂不可用」+ 说明（`LLM_BASE_URL` / `LLM_MODEL` 未配置，配置后点刷新重检） | disabled，placeholder「AI 未配置：在 .env 配置 LLM_BASE_URL / LLM_MODEL 后可用」 |
| 读取中 | spinner | 无 | disabled |

原型演示开关：「刷新」按钮 = 模拟 `.env` 变更后重新检测，在已配置/未配置间切换并 toast。发送时若收到 503（未配置）语义，追加 danger 错误气泡（复用横幅文案）。

## 三、聚焦条（三级视图焦点透传）

聚焦值随画布层级与选中项实时变化；右侧 chip「🔒 只读工具」title 补全评审批次文案「查询实时可用；建议 / 草稿等写操作需 editor」。

| 画布层级 | 聚焦条显示 | 聚焦来源 |
|---|---|---|
| 系统 | `系统 · dw_platform 数据仓库` | `S.selectedSystem`（无则 `S.seed`） |
| 数据集 | `数据集 · dws_order_daily 订单日汇总` | `S.selectedDataset` |
| 字段 | `字段 · dws_order_daily.gmv` | `S.selectedField`（ds + f） |

聚焦值作为对话上下文随请求透传（`/ai/chat` 的 focus 约定，04 §一）；示例问题第四条演示字段级聚焦问答。

## 四、工具集与权限（对齐设计方案 §6.2 + 08 批次 R8）

| 工具 | 对应 API（§15.1） | 类别 | 本页演示 |
|---|---|---|---|
| `search_systems` | `GET /systems?q=` | 只读 | 流 A 第 1 步 |
| `trace_system_lineage` | `GET /lineage/systems` | 只读 | 流 A 第 2 步（返回系统子图 → 出图联动） |
| `get_system_details` | `GET /systems/{id}` | 只读 | 流 B |
| `search_fields` / `trace_lineage` / `analyze_impact` / `get_field_history` | §13.6 附录 A8 | 只读 | 流 D（字段级） |
| `suggest_system_lineage` | `POST /ai/suggest/systems` | **写类** | 流 C；工具层按调用方角色校验，viewer 触发回传工具错误、不落库 |
| `suggest_lineage` / `draft_descriptions` | §13 | 写类 | 不在本页演示（04 已定稿） |

权限表现：

- **只读问答**：viewer/editor/admin 全员可用；
- **建议确认**：候选卡「确认 / 拒绝」按钮 viewer 置灰 + 行内提示「需要 editor 角色」（04 §3.6 与 08 R17 同一约定）；editor/admin 可操作；
- 确认/拒绝均写 `change_log`（`entity_kind='system_edge'`），主库提交后置 `graph_state.state='dirty'`，下次读请求自动重建 Kùzu（§4.7 版本化约定）。

## 五、工具轨迹卡与消息流

视觉沿用 04 §3.4–3.8（用户蓝底右对齐、AI 卡底左对齐、错误 danger 气泡、sending 虚线气泡），原型用自身 CSS 变量实现：

- **工具轨迹卡**：每次工具调用一张卡（对齐 [clew-hifi-prototype](../02_prototype/clew-hifi-prototype.html) 的 tool-card 形态），默认折叠为 `tool ✓ name(args)` 单行，点击展开参数与结果明细；轨迹成败用 ✓/✗ 颜色 + 字符双编码。
- **mini 结果行**：工具卡展开态内用「徽章 + mono 标识 + 说明」三段式行渲染工具返回（hop 徽章 / 精确徽章 / 置信度），与 04 的轨迹明细同族。
- **sending**：spinner + 「正在调用工具并组织回答…」；发送键切换为「停止」（danger），点击中断本轮剩余步骤并追加「本轮回答已停止」弱化提示（08 R17 的停止语义在 mock 中的等价物）。
- **清空对话**：头部「清空」按钮 → ConfirmDialog 二次确认 → 恢复欢迎语（08 R17）。

## 六、出图联动（`SystemGraphPayload` → `applyGraph`）

AI 回答携带 `graph` 时，前端把工具结果中的系统子图喂给与手工浏览**同一**渲染入口；本页以 `S.level/seed/direction/hops/selectedEdge` 应用实现：

| 联动类型 | 应用动作 | 画布表现 |
|---|---|---|
| 系统子图（流 A） | `level=system, seed=dw_platform, direction=up, hops=3` | 系统视图重算闭包，上游链入图 |
| 系统边选中（流 B） | `level=system, selectedEdge='finance->dw_platform'` | 边高亮 + 边抽屉行激活 + 详情面板展示证据下钻 |
| 字段链路（流 D） | `level=field, focus=dws_order_daily.gmv, selectedEdge=ds:15` | 字段视图点亮 3 跳链路 |

消息尾追加「画布已更新」success 条（数据集/系统数 + 连线数 + 「关闭并查看」按钮，关闭抽屉回看画布，04 §3.7）。联动不回退：关闭抽屉后画布保持 AI 给出的视图，用户可继续手工浏览。

## 七、系统级建议边生命周期（`suggest_system_lineage`）

```
AI 生成候选（source='ai'，confidence<1）→ 落 system_edge（editor 触发）
  → 画布：indigo 虚线 + 「AI」标签 + 关系实例行「AI 候选」徽章 + 顶栏待确认徽章 +1
  → 人工确认（editor+）：source ai→manual，虚线转实线、标签转「显式/×N」，
    写 change_log，graph 置 dirty（下次读请求自动重建）
  → 拒绝（editor+）：删除候选行，写 change_log(deleted)，graph 置 dirty
  → viewer：按钮置灰，提示「需要 editor 角色」；工具层兜底拒绝写库（R8）
```

- 原型初始 mock 含一条待确认候选：`crm → marketing`（conf 0.62，标签圈选推断）；演示流 C 运行时新增 `payment_gateway → finance`（conf 0.58，渠道对账推断）。
- 「AI 候选」过滤开关（工具栏已有）与建议生命周期解耦：过滤只控制可见性，不改变候选状态；确认转正后边不再受 AI 过滤影响。
- 顶栏待确认徽章 = `system_edge WHERE source='ai'` 计数（含演示环边开启时）。

## 八、Mock 对话流（示例问题）

空态示例问题 4 条，覆盖「系统链路问答 / 边证据解释 / 建议生成 / 字段级聚焦」四类；点击后回填并**立即发送**（对齐 clew-hifi-prototype 的 qchip 行为），未配置 LLM 时置灰：

| # | 示例问题 | 工具轨迹 | 画布联动 |
|---|---|---|---|
| A | 数仓的上游系统有哪些？数据是怎么汇进来的？ | `search_systems("dw_platform")` → `trace_system_lineage(dw_platform, up, 3)` | 系统视图 · 上游 3 跳子图 |
| B | 财务系统到数仓那条边是怎么来的？证据充分吗？ | `get_system_details("finance")` | 系统视图 · 选中 `finance→dw_platform` 边并下钻证据 |
| C | 帮我找可能漏掉的系统级血缘 | `suggest_system_lineage(scope=system)` | 画布出现候选虚线边 + 内联候选卡（角色差异演示） |
| D | gmv 这个指标是怎么算出来的？ | `trace_lineage("dws_order_daily.gmv", up, 3)` | 字段视图 · 点亮 gmv 上游链 |

回答内容必须与原型 mock 数据一致（hop 数、证据数、置信度），并显式引用存储分层（Kùzu 变长路径 / SQLite 证据表），保持「AI 是本系统查询工具的编排者」这一叙事。
